# u:on 포트폴리오 GitHub Pages 사이트 — 설계 문서

## 배경 / 목적

에이전시 **u:on**의 지난 프로젝트를 모아 보여주는 테크블로그 형식 포트폴리오 페이지를 GitHub Pages로 제작한다. 지금은 실제 프로젝트 콘텐츠가 다 정리되어 있지 않으므로, 우선 구조/틀을 완성하고 샘플 콘텐츠로 채운 뒤 추후 실제 프로젝트로 교체 가능한 형태로 만든다.

## 브랜드 자산 (제공됨)

- 로고: `logo.png` — 세리프체 워드마크 "u:on" (콜론이 점 두 개로 표현됨), 검정 텍스트
- 태그라인: "Weave the voices, Simulate the future."
- 연락처: `uon.data@gmail.com`
- 실제 과거 프로젝트 레퍼런스: `Desktop.pdf` — u:on이 진행한 "여론 분석 플랫폼" 랜딩페이지 목업 (밝은 배경 + 파랑/마젠타 그라데이션, SaaS 스타일)

## 기술 스택

순수 HTML/CSS/JS. 빌드 도구 없음. GitHub Pages user site(`username.github.io`)에 정적 파일을 그대로 push하는 방식으로 배포한다.

## 디렉토리 구조

```
/
├── index.html
├── projects/
│   ├── voice-of-public-platform.html   # 실제 사례 (여론 분석 플랫폼)
│   ├── sample-project-a.html           # placeholder
│   └── sample-project-b.html           # placeholder
├── css/
│   └── style.css
├── js/
│   ├── projects-data.js
│   └── main.js
└── assets/
    └── images/
        ├── logo.png
        └── (Desktop.pdf에서 추출한 스크린샷들)
```

- `projects-data.js`에 프로젝트 메타데이터 배열(제목, 요약, 태그, 썸네일 경로, 상세 페이지 링크)을 정의하고, `main.js`가 이를 읽어 `index.html`의 카드 그리드를 렌더링한다.
- 새 프로젝트 추가 시: (1) `projects-data.js`에 항목 추가, (2) `projects/` 폴더에 기존 상세 페이지를 복사해 내용 수정. 이 두 단계만으로 메인 페이지 카드가 자동 반영된다.
- 상세 페이지는 각각 독립된 정적 HTML 파일로, JS 템플릿 없이 직접 작성/수정 가능하다 (SEO 및 가독성 목적).

## 페이지 구성

### 메인 페이지 (`index.html`)
- **Hero**: u:on 로고 + 태그라인 "Weave the voices, Simulate the future."
- **About**: 회사 소개 2~3문장 + 연락처(`uon.data@gmail.com`)
- **Projects 그리드**: 카드형 리스트 (썸네일, 프로젝트명, 한 줄 요약, 태그, "자세히 보기" 링크). `main.js`로 동적 렌더링
- **Footer**: 저작권/연도, 연락처 반복

### 프로젝트 상세 페이지 (`projects/*.html`) — 케이스스터디 포맷
- 상단: 프로젝트명 + 대표 이미지
- 메타 정보: 클라이언트, 역할, 기간, 사용 기술 스택 (태그 형태)
- 본문: 문제/배경 → 접근 방식/솔루션 → 결과/성과
- 이미지 갤러리 자리
- 하단: 목록으로 돌아가기 링크

## 비주얼 디자인

- **다크 테마**: 배경 `#0a0a0a`~`#111` 계열, 오프화이트 텍스트
- **로고 처리**: 원본 로고가 검정 텍스트이므로 다크 배경 위에서는 흰색 배지(패널) 위에 로고를 얹거나 CSS 필터로 반전 처리
- **포인트 컬러**: 실제 랜딩페이지 목업에서 사용된 블루→마젠타 그라데이션을 다크 테마의 accent로 재해석 (버튼 hover, 링크, 태그 등 제한된 영역에만 사용)
- **타이포그래피**: 헤드라인(Hero 타이틀 등)은 세리프 폰트로 로고와 통일감을 주고, 본문/UI 텍스트는 산세리프 사용
- syncly.kr을 벤치마킹 레퍼런스로 참고하되(자동 조회 실패로 상세 스타일은 반영하지 못함), 위 다크 테마 방향을 그대로 유지

## 배포

- 현재 디렉토리는 git 저장소가 아니므로 작업 완료 후 `git init` 필요
- GitHub에 `<username>.github.io` 리포지토리를 생성하고 push (계정 정보 필요 시점에 사용자에게 안내)
